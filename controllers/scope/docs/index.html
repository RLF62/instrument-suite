START HERE

1. From connection to capture

  1. Connect the controller. Open Setup, enter the scope IP address or hostname (initially 192.168.1.78), press Test Connection and check the returned identity. Press Save.
  2. Connect your probes. Match each physical probe attenuation switch to its channel's Probe setting. Connect to the intended signal and a verified ground reference.
  3. View the signal. Return to the dashboard and choose Read settings. Enable the appropriate channels and use Run for continuous acquisition. Automatic screen refresh updates the image without replacing your control selections.
  4. Find a starting view. Press Autoset if needed, then review the resulting channel, timebase and trigger settings. Adjust scale and trigger for your signal.
  5. Add measurements. Select a channel and measurement type for each entry. Save entries, then Refresh. To show readings on the physical scope, select up to four On scope entries and press Apply selected to scope.
  6. Document the result. Save a PNG, download a channel CSV, or choose Download capture bundle for images, both available channel records and settings together.
Autoset can change the trigger sourceThe scope chooses a new automatic configuration. A trigger set to CH2 may become CH1. Check the readback after Autoset and reselect CH2 if your test requires it.

2. Read the scope display

Use automatic image refresh to follow the instrument screen. Acquisition status has its own update; measurements have their own optional refresh. Controls are read at startup, after explicit actions, or with Read settings. Use that button after changing settings at the front panel.

The last successful image remains visible if a request fails. The freshness label shows its update time and marks it stale after a failure. With automatic updates disabled, an image is a retained snapshot.

Channel recoloring is a dashboard display effectSelected colors recolor traces and channel-specific screen text in supported captures. The physical scope screen and original PNG retain the instrument's colors. Use Show original capture to compare the same frame.

Grid, generic text and trigger-marker palette entries are preserved. Overlapping traces cannot be separated from a single rendered pixel. Unusual graphics sharing a trace palette index may inherit its color; clipped edges can retain original color. Unknown or monochrome palettes fall back to the original with an explanation.

Customize Layout exposes Move handles, up/down alternatives, and Default/Half width/Full width choices. Adjust height with the lower-right corner or Shorter/Taller; Auto height fits the content again. Smaller fixed-height panels scroll internally. Finish with Done customizing. Order and sizes are saved in this browser; Reset Layout clears both. Narrow screens use full width and automatic height while retaining desktop preferences. Layout changes do not change scope settings.

3. Acquisition, channels and trigger

ControlWhat it does / when to use it
Run / StopRun selects continuous acquisition. Stop retains the acquired record for inspection.
SingleArms one sequence and waits for its trigger. In Average mode, a sequence includes the averaging count. Waiting is a valid state, not a communication failure.
AutosetAutomatically adjusts channels, timebase and trigger. Controls and image refresh after bounded status polling.
Sample / Peak Detect / AverageSample records samples; Peak Detect preserves extrema within intervals; Average reduces uncorrelated noise across acquisitions. Choose the Average count only while Average is selected.
Menu OffSends the documented CLEARMENU command to dismiss a menu. No acquisition-complete wait is used.
Channel display, scale, position, offsetEnable CH1/CH2, set volts/div, move the trace in divisions or adjust voltage offset. Readback shows accepted settings.
Coupling / Probe / Bandwidth / InvertChoose DC, AC or ground coupling; match probe attenuation; limit bandwidth to 20 or 150 MHz, or Full; invert the channel if required.
HorizontalSets the main seconds/div timebase. Use a smaller value to examine fast edges or a larger one to see longer events.
Edge triggerSelect source, rising/falling slope, voltage level and Auto/Normal mode. More complex trigger configurations remain front-panel settings.

Settings are read back after application. Instrument rounding, probe detection and mode restrictions can produce a different accepted value; the dashboard reports that result.

CLASSIC VIEW

Use the interactive front panel

Open Classic front panel from the controller. Cyan guides mark clickable areas on the front panel photograph; they are control guides, not physical knobs. Hover or focus a guide to see its label. The Classic page shares the connected scope and settings with the standard dashboard.

Front panel controlController action
RUN/STOP, SINGLE SEQ, AUTOSETRUN/STOP toggles acquisition based on the latest scope readback; SINGLE SEQ arms one sequence; AUTOSET asks the scope to choose a starting configuration. The separate Run and Stop controls above the image give explicit commands. Check the status after each action.
CH 1, CH 2, OFF; vertical knobs and menuSelect and enable a channel, turn the selected channel off, or open its scale/position and vertical settings. Numeric knob popups read the current value; press Apply to send a change to the real scope.
Horizontal and trigger controlsSet timebase, horizontal options, trigger level, source and other exposed settings in their popups. FORCE TRIG and SET TO 50% issue commands to the scope. B trigger opens its own settings.
SELECT, COARSE, general-purpose knobWith display cursors off, SELECT cycles trigger level, CH1 position, CH2 position and horizontal timebase. Click the knob guide to open the current numeric setting; use minus/plus or type a value, then Apply to change the scope. COARSE switches the size of the popup steps. The knob guide stays over the knob; the two small guides stay over the SELECT and COARSE buttons.
CURSOR and the general-purpose controlsCURSOR enables the simulated display cursors. SELECT then switches cursor A/B, and the general-purpose popup's minus/plus moves the active cursor. COARSE changes cursor step size. These cursor movements affect the simulated waveform only and send no scope command.
WAVEFORM INTENSITYOpens a brightness slider and Apply button for the real scope screen. The guide is positioned on the intensity knob; this does not alter the simulated display brightness.
MEASURE, SAVE/RECALL, MATHOpen the measurement list, saved setup controls or Math operation/display popup. Math changes affect the real scope Math waveform while the simulated CH1/CH2 display remains two channels.
DISPLAY, QUICKMENU, UTILITY, REF, PRINT, MENU OFFOpen display options, scope screen options, controller Setup or reference waveform controls; print the scope screen; or dismiss a scope menu.

Changes to numeric settings are not sent while you merely step or type in a popup. Press Apply to scope, then check the readback. If the scope is stopped, press Run to resume live acquisition. Refresh the page if your browser still shows older hotspot positions after an update.

4. Build your measurement list

  1. Select CH1 or CH2 and Frequency, Period, Peak-to-peak, RMS or Mean for each entry.
  2. Add or remove entries, up to 20, and save the list. This saves dashboard preferences; it does not apply on-screen slots.
  3. Press Refresh or enable automatic measurement refresh.
  4. For the instrument screen, check On scope for at most four entries and press Apply selected to scope. Unselected scope slots are turned off. The channel must already be enabled.

A matching active on-screen slot is read directly, reducing differences between dashboard and scope. Other entries use temporary immediate measurements, with their prior source/type restored. Readings and images are sequential and may represent different acquisitions.

Warnings keep their meaningA finite reading accompanied by low-signal or limited-resolution warnings is shown with an explanation. Invalid, nonfinite, sentinel and off-channel results are Unavailable. Expand details for the raw qualifier, response and source. A stale retained value is not a fresh measurement.

5. Save a screen or waveform

Images

Save original PNG downloads the scope's unmodified capture. Save displayed PNG saves the currently displayed original or recolored view. Originals are retained for the same frame in a 16-capture memory cache; refresh after eviction or a service restart.

Channel CSV

  1. Ensure the channel is enabled and has acquired a useful record.
  2. Choose CH1 or CH2 download.
  3. Read the metadata comments before using the samples. The file includes channel, identity, host read time, record scaling and acquisition state.
A CSV may contain an older stored recordChanging a knob does not guarantee the stored record has been reacquired. Scaling comes from that record's own preamble. The timestamp is the controller's read time, not the scope's trigger time. Acquire a new record with Run or Single when you need new data.

Capture bundle

Download a ZIP containing original and displayed screen images, available CH1/CH2 CSVs, measurements, current settings and a manifest. If a channel is unavailable, its explanation replaces that CSV and the bundle is marked partial. Transport failure stops the download. Images, settings and channels are read sequentially; a running scope can change during collection. The controller does not stop, resume or rearm acquisition to make a bundle.

6. Save and recall a setup

  1. Establish a working configuration and choose an informative personal name.
  2. Save the current scope settings. Reusing an existing personal name replaces that setup.
  3. Select a saved setup and review its included values before Recall.
  4. After recall, inspect accepted readback and any differences. Recheck the physical probes and wiring yourself.

Personal presets include both channels' enable/probe/scale/position/offset/coupling/bandwidth/invert, main timebase, acquisition mode/count and Edge trigger type/mode/source/slope/level. They exclude Run/Stop/Single state, waveform data, network address, colors, measurement selections/slots, layout and advanced measurement/trigger parameters. Up to 50 personal setups are supported.

A preset cannot move a probe switch or wireRecalling settings changes the instrument. It cannot attach probes, move ground clips or change physical attenuation. Confirm all connections before relying on the resulting voltages.

8. Connection, colors and backup

Scope connection address tells the controller where to find the scope. It does not change the IP configured on the scope itself. Enter an IPv4 address or hostname without a scheme, port or path. Test Connection checks the entered value without saving; Save retains it across restarts.

Advanced settings contains a 1–30 second per-operation timeout, default 6 seconds. A request can contain several operations. Separate CH1/CH2 colors have a Reset to default colors button.

  1. Choose Download setup backup to export connection/timeout, colors, saved measurement entries and personal presets.
  2. To restore, choose the JSON file and Review backup. Read the replacement summary.
  3. Press Restore reviewed settings. A previous-settings backup is offered automatically. If preferences changed after review, review again.

Restore affects controller preferences only. It does not recall a physical scope setup, change the scope's network configuration or restore browser-local panel layout.

9. Troubleshooting

SymptomChecks and recovery
Offline / connection timeoutOpen Setup; check address and returned identity with Test Connection. Check instrument power, Ethernet and routing. A controller timeout releases its communication lock so another request can recover.
Unavailable measurementCheck channel enabled, signal amplitude and trigger stability. Expand details. Frequency/period require a useful periodic signal. Qualifier 541 means low amplitude, 542 unstable distribution, 543 limited resolution; an invalid numeric value remains unavailable.
Dashboard differs from screenMatching display slots are read directly. Images/readings still arrive at separate instants. Check freshness, measurement type, source and warning details.
Stale image or readingsThe old successful result remains visible with a stale indication. Correct the connection and refresh. Read settings updates controls after front-panel changes.
Old or flat CSVThe stored record may be old or have no useful acquired data. Acquire a new record with a suitable trigger; changing settings alone is insufficient.
Single stays waitingCheck trigger source, level and slope. Waiting is expected until an appropriate trigger. Menu Off does not wait for acquisition completion.
Autoset changed CH2 trigger to CH1Autoset chooses its own trigger. Reselect CH2 after reviewing the resulting configuration.

Reset e*Scope interface

  1. If the scope's Ethernet service remains stuck, first check its front panel and network.
  2. Open the scope's own built-in e*Scope page using the address saved in Setup.
  3. Use its configuration page's Reset Interface / Reset e*Scope interface control and allow about one minute for recovery.
  4. Return here, Test Connection, then read settings and refresh.

This resets the instrument's communication interface, separately from the Pi web service. No automatic scope reset is performed. A controller restart cannot guarantee recovery from an instrument-side firmware stall.

ADVANCED / MAINTENANCE

Installation, update and recovery

This is a LAN development build without application authentication. The standalone controller uses port 8081; no HP controller files or Nginx changes are needed. Commands below match the deployed user-service layout.

Install source on Raspberry Pi OS

Put the supplied source (including docs/) in ~/tektronix-controller. Python 3 and venv support are required.

python3 -m venv ~/tektronix-controller-venv
~/tektronix-controller-venv/bin/pip install -r ~/tektronix-controller/requirements.txt
mkdir -p ~/.config/systemd/user
cp ~/tektronix-controller/tektronix-controller.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now tektronix-controller.service

Open http://PI_ADDRESS:8081/setup. The supplied service uses %h for the user's home directory, one Gunicorn worker and four threads. On the test Pi, Linger=no: automatic user-service startup requires login. The live deployment enables account lingering for unattended startup. A separate clean installer and physical Android touch operation remain unverified.

Service management

systemctl --user status tektronix-controller.service
systemctl --user restart tektronix-controller.service
systemctl --user stop tektronix-controller.service
journalctl --user -u tektronix-controller.service -n 50 --no-pager

Full backup before an update

Setup export backs up preferences, not the application. A full backup should include source, docs, preferences and the user-service definition. Run as the controller's user:

systemctl --user stop tektronix-controller.service
tar -czf "$HOME/tektronix-backup-$(date +%Y%m%d-%H%M%S).tar.gz" \
  -C "$HOME" tektronix-controller .config/systemd/user/tektronix-controller.service
systemctl --user start tektronix-controller.service

Inspect the archive with tar -tzf BACKUP.tar.gz. For an update, stage the new source first; preserve connection.json, appearance.json, measurement-selection.json, presets.json and setup-backups/. Stop the Tektronix service, replace application files and docs only, install requirements if needed, and restart. Check Setup, identity, image and one measurement. Do not run opt-in hardware tests during an in-progress capture.

Rollback

Stop the Tektronix service. Keep a copy of newer preferences if needed. Extract the chosen full backup under its original home directory, reload user service definitions and start the service. Restore preferences from a reviewed Setup backup if appropriate.

systemctl --user stop tektronix-controller.service
tar -xzf BACKUP.tar.gz -C "$HOME"
systemctl --user daemon-reload
systemctl --user start tektronix-controller.service

Waveforms and communication

Version 0.3.1 also bounds initial DNS, RPC discovery and TCP connection. Timeout discards the transport and releases the communication lock; the HP application uses a separate process.

The front panel is labeled TDS 3032B; the connected instrument has returned TDS 3052B firmware v3.27. Instrument details display its returned identity. No model-configuration commands are sent.

All scope traffic uses a thread lock plus process file lock. Timeout discards the unusable RPC transport and releases locks in finally. Keep one Gunicorn worker. Independent applications controlling the same scope are outside this protection. The controller does not use blocking *OPC? or *WAI to wait for an armed acquisition.

CSV conversion

WAVFRM? returns the stored record's preamble and samples. Transfer uses signed 16-bit big-endian values, with binary-block length, point count, units and finite scaling validated.

time_seconds = xzero + xincr * (zero_based_point_index - pt_off)
voltage_volts = yzero + ymult * (raw_sample - yoff)

Sample/Average CSVs contain time_seconds, voltage_volts and raw_sample. Peak Detect/Envelope records contain time_seconds, voltage_min_volts, voltage_max_volts, raw_min and raw_max, one row per min/max pair. A verified 10,000-value Peak Detect record produced 5,000 rows. No additional probe multiplier is applied.

Transfer source/range/width/representation/order/encoding are saved, restored in finally and verified. Export sends no acquisition-state commands. A naturally completed Single is not rearmed. Source timestamp is host UTC read time, not instrument trigger time.

The tested firmware accepts CHn:PROBE 10 as 10× attenuation. Its scaling behavior differs from the manual's inverse-gain example; actual readback is authoritative. Detected probes can enforce their factor.

Original/effect images use a checked indexed-PNG palette. A prior real capture changed 8,474 trace pixels and 2,603 channel-text pixels while 296,123 other pixels retained identical RGB values.

Full prior technical notes, baseline history and verified limitations remain in the complete source reference. Programmer manual: Tektronix 071-0381-03 (external; the guide itself works offline).

Verification and remaining limits

Automated: 26 Python tests pass, covering waveform scaling, transfer restoration/failure, timeout lock release, image effects, warning qualifiers, matching measurement slots, backup validation and rollback, partial bundles, and recipe safeguards. Six Node regression scenarios cover image-only refresh, action priority, decoded-frame handoff, original-image handling and freshness states.

cd ~/tektronix-controller
~/tektronix-controller-venv/bin/python -m unittest -v \
  test_scope_io test_screen_effect test_archive_tools test_ethernet_transport
node test_refresh.js

Verified in v0.3.0: a complete capture ZIP with both 10,000-sample CSVs and acquisition remaining running; matching on-screen measurement reads; identical-preference backup/restore with downloadable prior settings; rejection of invalid files and stale restore reviews. The gallery shows actual controller screenshots.

Previously verified on the connected scope: both channel CSVs, running/stopped/armed Single exports, settings/immediate/transfer restoration, acquisition/channel controls, preset recall, four measurement slots, Autoset readback and image, Menu Off while Single is armed, communication serialization, offline Setup and persistence across service restart.

Not yet verified: Sony examples on the changer, exact missing elevator timing/trigger settings, Menu Off with an actual DHCP status box, physical Android touch operation, clean installation on a second Pi and unattended startup. verify_live.py is an opt-in test that temporarily changes instrument settings; never run it automatically or during a capture you need to preserve.
